System Overview

ccmon is a single Go binary that monitors all active Claude Code sessions on the local machine. It uses Bubble Tea for TUI rendering, with two concurrent background goroutines (watcher and reader) that emit typed messages to communicate state changes.

Message Specifications

SessionsUpdatedMsg
  • Sessions: []*Session — all current sessions
  • Emitted by: Watcher on CREATE/REMOVE in ~/.claude/sessions/
  • Frequency: Instant (fsnotify) or ~2s (polling fallback)
UnreadMsg
  • SessionID: string — which session has new activity
  • Emitted by: Watcher when non-selected session JSONL grows
  • Frequency: Instant (fsnotify) or ~2s (polling)
ConversationMsg
  • SessionID: string — which session this belongs to
  • Entries: []ConversationEntry — parsed lines from JSONL
  • Emitted by: Reader polling the selected session JSONL
  • Frequency: ~500ms, only when file grows
WatchErrorMsg
  • Err: error — fsnotify setup failure
  • Emitted by: Watcher on NewWatcher() or Add() failure
  • Effect: UI shows amber warning "File watching unavailable — polling every 2s"

Goroutine Lifecycle & Reader Management

1
main() starts — Creates Bubble Tea program, initializes Model, starts Watcher goroutine, registers OnSelectSession callback.
2
Watcher goroutine runs — Monitors ~/.claude/sessions/ for session create/remove events. Watches selected session JSONL for growth (unread indicator). Emits SessionsUpdatedMsg, UnreadMsg, WatchErrorMsg to Model.
3
User selects session (Enter) — Model.selectCurrent() finds session, calls onSelectSession(s), clears conversation entries, resets scroll, clears unread flag.
4
main.go creates fresh Reader — OnSelectSession callback: cancels previous Reader's context (if any), creates new context, constructs new Reader (stateless), starts new goroutine go r.Run(ctx).
5
Reader goroutine runs — Polls selected session JSONL at 500ms intervals. Reads new bytes, parses lines into ConversationEntry. Emits ConversationMsg to program.Send(), which Model receives.
6
User selects different session or quits — Model calls onSelectSession() with new session (or nil). main.go's callback cancels previous Reader context. Reader.Run() returns, goroutine exits. New Reader created if new session selected.
Key design: Reader is stateless between sessions. Each new selection creates a fresh Reader struct with a fresh context. Old reader's context is cancelled before new reader starts. This avoids data races on the offset field.

Architectural Design Notes

Message-Driven Architecture: Watcher and Reader don't call Model directly. They emit typed tea.Msg values to the Bubble Tea program via program.Send(). Model handles all messages in Update(). This decouples goroutines from TUI logic and prevents race conditions.
Reader Statelessness: Each session selection creates a brand-new Reader instance. The old reader's context is cancelled. This eliminates data races on the offset field that tracks file position. No need for synchronization primitives (mutexes) for reader state.
fsnotify with Fallback: Watcher tries fsnotify first. If setup fails, it falls back to 2-second polling and emits WatchErrorMsg so the UI can warn the user. Sessions can always be monitored even if inotify is unavailable.
Lazy JSONL Resolution: FindJSONLPath is called during session load, not on startup. Only sessions with a valid JSONL path can be selected and read. Missing files don't cause errors, the right panel just shows "No conversation history yet".
Unread Tracking (In-Memory Only): The unread indicator (yellow dot + ✦ on session name) is stored in Model's unreadSet map. It's cleared when the session is selected or when the TUI restarts. No persistent storage.
